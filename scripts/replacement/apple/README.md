# Apple validation workflow

The iDex app includes the trained FP32 package and builds normally with Xcode27.1. This standalone tooling checks a newly exported package without changing app membership, replacing the bundled artifact, or installing over an existing phone app.

## Source and Core ML parity

From the repository root:

```sh
mkdir -p artifacts/apple-validation
xcrun swiftc -O -parse-as-library -target "$(uname -m)-apple-macosx13.0" \
  scripts/replacement/apple/AppleValidationCore.swift \
  scripts/replacement/apple/ValidateModels.swift \
  -o artifacts/apple-validation/validate-models
```

The CLI accepts two comparison roles, `baseline` and `candidate`; these are arbitrary reference/experimental paths, not app-default selectors. For active-model reproduction, supply the bundled FP32 package as the reference and the new FP32 export as the experimental package. Each role needs logits generated by its own exact source checkpoint. Never compare one model numerically against another model's unrelated logits.

```sh
python scripts/replacement/fixtures.py --checkpoint /path/to/your/checkpoint.pt \
  --reference-checkpoint /path/to/reference/checkpoint.pt \
  --out artifacts/replacement/apple-fixtures
artifacts/apple-validation/validate-models \
  --baseline iDex/Recognition/KantoClassifier.mlpackage \
  --candidate /path/to/new-fp32.mlpackage \
  --labels iDex/Recognition/pokemon_labels.json \
  --manifest artifacts/replacement/apple-fixtures/manifest.json \
  --output artifacts/apple-validation/parity.json \
  --compute-units cpuOnly --atol .001 --rtol .0001 --require-references
```

Use the same checkpoint for both source roles when checking a re-export of the same trained artifact. The fixture generator needs a locally built validation manifest and authorized source images; these are deliberately not included in the upload. File examples are schemas, not evidence.

The shared Swift preparation mirrors `ScanImagePreparer`: bounded ImageIO decode, EXIF orientation/mirroring, centered square, sRGB, white alpha composition, high-quality drawing and Core ML image-feature `scaleFill`. Use `--dump-inputs /path/to/new-rgb-directory` to write exact post-feature row-major RGB uint8 bytes. If pixels differ from the source framework, regenerate source logits from these exact bytes before concluding the model conversion is wrong. Keep image/label/checkpoint hashes with each local report.

Input/output names, fixed dimensions, pixel format, supplied label ordering/count, finite outputs and source-reference parity are checked. Pass the same `labels-national.json` used for training for a national candidate; both compared models must use that exact label order (the historical 151-class model cannot be paired with a 1025-class candidate). For conversion parity, use the same candidate in both roles and its corresponding source references. Reports retain full logits/errors. Exit1 means supplied parity failed; exit2 means malformed input/runtime failure. Without `--require-references`, an exploratory exit0 can still mean incomplete parity and is not a passing conversion gate. Repeat every intended compute policy and inspect the serialized graph/normalization contract separately.

## Physical iPhone harness

`PhysicalDeviceValidationTests.swift` and `AppleValidationCore.swift` can be added to a separate local iOS XCTest target with nonisolated default actor isolation. Do not include the macOS CLI's `@main`. Copy precompiled model resources, exact ordered labels and your authorized fixtures/reference files into that test target, preserving relative paths. Configure a local copy of `AppleValidationConfig.example.json`. A phone cannot read the Mac's absolute source paths.

Run Release on the actual target device after obtaining installation/signing permission for a separate test app. Preserve existing app/data; no credentials, trust, account or security changes are required by these source files. The harness deliberately skips Simulator as physical timing evidence. It checks references before timing and records all four compute-unit configurations, loading, preparation, synchronous prediction/output reading, end-to-end samples, sampled process-resident memory and thermal state.

Use at least100 measured warm samples after warm-up, a bounded sustained workload, counterbalanced model/policy order and a common fixture cycle. Keep first-load/cache definitions explicit; load-only reopens are not proven cold-start measurements. Profile actual placement separately where Instruments exposes evidence; selecting `.all` or `.cpuAndNeuralEngine` is not itself proof of ANE execution. Save raw JSON/xcresult/trace files locally in ignored artifacts, not in the Git commit. Do not upload training photos or private device logs.

## App selection

The tracked `KantoClassifier.mlpackage` is already the selected FP32 default. A normal clone/build needs no launch flag or separate candidate resource. Experiments should use a disposable checkout and new output files, preserve labels/preprocessing, and retain a rollback copy before a deliberate future selection. See the current model notes for the measured limits and existing app acceptance heuristics.
